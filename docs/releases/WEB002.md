# SPORT Web — WEB002

## Objectif
Faire du navigateur un véritable répertoire de consultation SPORT, tout en gardant le Web strictement en lecture seule.

## Évolutions
- chargement Firestore par lots de 250 activités ;
- pagination locale 25 / 50 / 100 activités par page ;
- bouton de chargement progressif et bouton « Charger tout » ;
- recherche accent-insensible dans titre, fichier, matériel, source et repères ;
- filtres sport, année, matériel, repère, source, distance minimale et D+ minimum ;
- tris date, distance, dénivelé et durée ;
- compteur de filtres actifs et remise à zéro en un clic ;
- fiche activité enrichie ;
- statistiques principales mises en avant ;
- allure moyenne pour la course, vitesse moyenne pour le vélo ;
- matériel, source, repères, fichier, note et description ;
- navigation activité précédente / suivante dans le résultat filtré ;
- lien direct partageable vers une activité via le hash `#activity=...` ;
- interface responsive téléphone, tablette et ordinateur.

## Lecture Firestore
WEB002 lit :
- `/sport_users/{uid}/meta/state`
- `/sport_users/{uid}/activities`
- `/sport_users/{uid}/landmarks`
- `/sport_users/{uid}/activity_landmarks`
- `/sport_users/{uid}/records`

## Sécurité
WEB002 reste strictement en lecture seule. Le workflow CI refuse la publication si `web/app.js` introduit une API Firestore d'écriture.

## Performance
Le catalogue ne charge pas automatiquement les milliers d'activités :
- 250 activités au démarrage ;
- 250 supplémentaires à la demande ;
- « Charger tout » reste une action explicite.

Les filtres et la recherche portent sur les activités déjà chargées. Le bandeau indique en permanence combien d'activités sont chargées sur le total Firestore.
