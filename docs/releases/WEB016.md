# SPORT Web · WEB016 · SYNCHEALTH001

## Objectif
Dernière consolidation du socle d’interopérabilité avant CARTO002.

## Santé des trois clients
Le Web écoute `sync_health` et affiche pour chaque client connu :
- dernière présence ;
- dernier échange ;
- nombre de mutations en attente ;
- état OK / synchronisation / attente / hors ligne / erreur / ancien ;
- dernière erreur publiée.

Le client Web publie un heartbeat toutes les 60 secondes.
Un client sans nouvelle depuis 15 minutes est affiché comme ancien/inactif, sans être considéré comme une erreur.

## Reprise réseau Web
Les mutations métier ordinaires déclenchées pendant que le navigateur signale l’absence de réseau
sont conservées dans `localStorage`. Au retour de l’événement `online`, elles sont réémises dans
l’ordre automatiquement.

Les opérations batch complexes (recalcul massif des records, renommage matériel avec cascade)
restent volontairement exclues de cette file : elles exigent une connexion active afin d’éviter
toute ambiguïté atomique.

## Android
Le compagnon SPORT v217 / SYNCHEALTH001 publie automatiquement dans `sync_health` :
modèle de l’appareil, version Android/SPORT, dernière présence, dernier échange, file Firebase et erreur éventuelle.

`sync_health` ne fait pas partie du bootstrap métier et ne modifie pas `expectedDocuments`.
