# SPORT Web · WEB006 · INTEROP001

## Priorité

WEB006 fait passer SPORT Web d'un troisième écran de consultation à un véritable troisième client SPORT.

Le principe visé est désormais :

`Téléphone ⇄ Firestore ⇄ Tablette ⇄ Web`

Une intervention compatible sur l'un des trois clients doit être propagée aux deux autres.

## Première tranche d'écriture Web

WEB006 autorise volontairement un périmètre restreint et contrôlé :

- modification du titre personnalisé d'une activité ;
- modification de sa note personnelle ;
- ajout d'un repère ;
- incrément / décrément du compteur d'un repère ;
- suppression d'un repère lorsque son compteur revient à zéro.

Les autres données restent consultatives.

## Transport Web → Android

Chaque modification Web est écrite atomiquement dans un `writeBatch` :

1. mise à jour du document métier (`activities` ou `activity_landmarks`) ;
2. création d'un événement dans `sport_users/{uid}/changes/{eventId}` ;
3. mise à jour légère de `meta/state`.

L'événement suit le contrat déjà consommé par `FirebaseSportBridge.pullRemoteBlocking()` sur Android :

- `eventId`
- `deviceId`
- `firebaseSeq`
- `sourceChangeSeq`
- `table`
- `rowKey`
- `operation`
- `changedAtMs`
- `publishedAt`
- `row`

Aucune nouvelle version Android n'est requise pour cette première tranche : le récepteur générique présent en v214/v215 sait déjà appliquer `activities` et `activity_landmarks`.

## Transport Android → Web

WEB006 écoute en temps réel la collection `changes` avec `onSnapshot`.

Quand un téléphone ou une tablette publie une mutation :

- une modification `activities` met à jour l'activité déjà chargée dans le navigateur ;
- une modification `activity_landmarks` met à jour immédiatement les repères de la fiche ;
- l'interface signale `Modification Android reçue`.

## Test d'acceptation à trois clients

1. Web : ajouter un repère à une activité.
2. Vérifier qu'il apparaît automatiquement sur téléphone et tablette.
3. Téléphone : modifier le compteur de ce repère.
4. Vérifier la mise à jour automatique sur Web et tablette.
5. Tablette : retirer le repère.
6. Vérifier sa disparition sur Web et téléphone.

Ce test valide le triangle d'interopérabilité pour `activity_landmarks`.

Un second test peut utiliser le titre ou la note :

1. Web : modifier le titre ou la note.
2. Vérifier la propagation sur les deux appareils Android.
